# BPMN 可视化设计器集成 TODO（2026-04-09）

## 1. 目标与结果定义
将 `RuoYi-Flowable-Vue3` 的 `bpmn.js` 可视化流程编辑能力集成到 `approval-system`，替换管理员手工编辑 BPMN XML 的主流程。

第一阶段交付定义为“最小可用”：
- 可视化编辑为默认入口；
- 支持基础工具栏（保存、缩放、撤销、重做）；
- 保留源码 XML 兜底编辑（默认折叠，可展开）；
- 不做完整属性面板迁移；
- 保持现有“保存草稿/发布流程/节点配置”链路稳定。

## 2. 本次范围（In Scope）
- 前端：`approval-system/frontend`
- 主页面：`AdminWorkflowsView`
- 后端：在复用现有发布链路基础上，补齐必要校验与结构化错误码
- 引擎：固定 `Flowable`

## 3. 非目标（Out of Scope）
- 不做 RuoYi 全量属性面板（监听器、扩展属性、复杂条件表达式）
- 不做多引擎切换（Camunda/Activiti）
- 不做 token simulation
- 不在本阶段实现“表单指令自然语言解析并发起流程”

## 4. 已确认的产品决策（必须执行）

### 4.1 交互与编辑模式
- [ ] 默认进入“可视化”模式。
- [ ] 提供“可视化/源码”切换。
- [ ] 源码 XML 编辑区默认折叠，可手动展开。
- [ ] 源码手改后，不实时回灌画布；通过“重载画布”按钮手动同步。

### 4.2 设计器能力边界（第一阶段）
- [ ] 工具栏仅包含：保存、缩放、撤销、重做。
- [ ] 支持基础 BPMN 拖拽建模与 XML 回写。
- [ ] 不迁移完整右侧属性面板。

### 4.3 草稿初始化与模型约束
- [ ] 新建草稿时如 `bpmnXml` 为空，自动生成默认骨架流程（开始 -> 审批 -> 结束）。
- [ ] 每个版本仅允许 1 个 BPMN `Process`。
- [ ] 固定 Flowable moddle 扩展，不提供引擎切换。

### 4.4 一致性与阻断规则
- [ ] `processKey` 与 BPMN 主流程 `process id` 不一致时：**保存草稿阻断**。
- [ ] 上述一致性校验：**前后端双校验**（前端早反馈，后端防绕过）。
- [ ] 节点配置采用“手动同步”：
  - [ ] 日常编辑不自动刷新节点配置；
  - [ ] 发布前若节点配置与 BPMN 不一致则阻断。
- [ ] 发布因节点不一致阻断时：前端提示并自动跳转“节点配置”Tab。

### 4.5 异常处理与可恢复性
- [ ] BPMN XML 导入画布失败时：自动切到源码模式并展示错误详情。
- [ ] 用户修复 XML 后，可通过“重载画布”恢复可视化编辑。

## 5. 后端错误协议（新增）
为保证前端可精确处理发布/保存失败场景，补充结构化错误码。

- [ ] 统一错误返回包含：`code`、`message`（必要时带 details）。
- [ ] 至少新增以下错误码：
  - [ ] `BPMN_KEY_MISMATCH`：`processKey` 与 BPMN 主流程 ID 不一致
  - [ ] `BPMN_PROCESS_COUNT_INVALID`：流程定义包含非单一 Process
  - [ ] `BPMN_XML_INVALID`：BPMN XML 非法或不可解析
  - [ ] `NODE_CONFIG_MISMATCH`：节点配置与 BPMN 节点不一致
  - [ ] `FORM_VERSION_REQUIRED`：发布时缺失表单版本
- [ ] 前端按 `code` 做稳定交互（例如跳转节点配置页）。

## 7. 验收标准（DoD）

- [ ] 管理员无需手写 XML 即可完成流程编辑与保存。

- [ ] 现有审批主链路能力不回退。
